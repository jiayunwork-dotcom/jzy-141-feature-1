# 连锁便利店周销量 Holt–Winters 预测与回测平台

面向补货计划员的内部网页工具：上传/选择周销量序列 → 后台拟合 Holt–Winters
（加法/乘法季节，趋势可选「无 / 加法 / 加法阻尼」）→ 页面查看拟合曲线、
未来若干周点预测与预测区间 → 滚动原点回测并与**季节朴素法**对照。
数值内核（递推、优化、区间、回测）全部手写，仅依赖 NumPy，**不调用**
statsmodels 等现成实现。

- 后端：Python 3.12 + FastAPI + SQLAlchemy + PostgreSQL 16
- 前端：React 18 + Vite + TypeScript + Recharts
- 后台任务：有界线程池（`app/jobs.py`），多计划员处理不同序列互不阻塞
- 编排：`docker compose` 三服务（db / backend / frontend(nginx:1.27-alpine)）

## 一键启动

```bash
docker compose up --build
# 浏览器打开 http://localhost:8080
```

首次启动后端会等待数据库就绪并自动建表。示例数据：
`sample_beverage_sales.csv`（164 周、带夏季高峰与节假日峰值）。

## 页面说明

1. **序列列表**：上传 CSV（两列：周起始日期、销量）。日期按 7 天步长
   校验；缺周会列出具体日期并在序列上打标记；非整周对齐（间隔不是 7 的
   整数倍）直接阻止导入并提示原因。
2. **拟合页**：
   - 原始值、拟合值、未来点预测与置信带同图展示；
   - 参数面板可勾选**锁定 α/β/γ/φ** 中任意若干个（手填数值），其余照常
     自动优化，点击后立即在后台重算；
   - 展示参数、SSE、AIC、残差（标准差等）、最终状态；
   - 自动选型时列出全部 6 种组合的 AIC/SSE/参数/可行性（评分卡），
     最优组合标星；
   - 同一序列的每次拟合都入库，可在底部列表中单选比较。
3. **回测页**：设置首个原点、步长 h、原点步长、置信水平与区间方法；
   逐原点列出 MAE/MAPE/MASE，并与季节朴素法并排，表格汇总 + 单原点
   逐步对照。页面所有数字均由后端计算。

所有计算在后台任务中执行，页面显示进度条与阶段；任务结果（拟合/回测）
落 PostgreSQL，可重复查看与比较。

## 模型定义（与代码一一对应）

记水平 `l_t`、趋势 `b_t`、季节指数 `s_t`，季节周期为 `m`（周数据默认 52）。

**加法季节**

```
ŷ_t = l_{t-1} + φ b_{t-1} + s_{t-m}
l_t = α (y_t - s_{t-m}) + (1-α)(l_{t-1} + φ b_{t-1})
b_t = β (l_t - l_{t-1}) + (1-β) φ b_{t-1}
s_t = γ (y_t - l_t) + (1-γ) s_{t-m}
```

**乘法季节**（加法式同上改为比值：`ŷ_t=(l_{t-1}+φb_{t-1})s_{t-m}`，
`l_t=α y_t/s_{t-m}+(1-α)(l_{t-1}+φb_{t-1})`，
`s_t=γ y_t/l_t+(1-γ)s_{t-m}`）。

`φ=1` 对应无阻尼；趋势选「无」时没有 `b` 与 `β`。

候选组合共 6 种：趋势 ∈ {无, 加法, 加法阻尼} × 季节 ∈ {加法, 乘法}。

### 参数取值区间（优化约束）

| 参数 | 含义 | 区间 |
|---|---|---|
| α | 水平平滑 | [0.001, 0.999] |
| β | 趋势平滑 | [0.001, α] |
| γ | 季节平滑 | [0.001, 0.999] |
| φ | 阻尼 | [0.80, 0.98] |

目标：最小化**样本内一步预测误差平方和**（SSE），且 SSE 只统计从第
`2m+1` 个观测开始的真正「样本外一步」误差（前两个完整季节用于初值）。
优化器是手写的多起点 Nelder-Mead，在 logit 变换后的无约束空间搜索并以
确定性起点网格运行，因此**同一输入重复拟合结果一致**。锁定的参数从搜索
向量中移除，只优化剩余参数。

### 初始分量（前两个完整季节，文档化的固定规则）

设第 1、2 个季节的均值为 `L0、L1`：

- 初始趋势 `b = (L1 - L0)/m`；
- 初始水平（位于第 `2m-1` 期末）`l = L1 + (m-1)/2 · b`；
- 加法季节初值 `s_i = y_i - (L0 + (i-(m-1)/2)b)`（i=0..m-1），再中心化
  使 `Σ s_i = 0`；
- 乘法季节初值 `s_i = y_i / (L0 + (i-(m-1)/2)b)`，再归一化使
  `mean(s_i)=1`；
- 无趋势时令 `b=0`、基准线为 `L0/L1`。

归一约定在拟合后始终保持（加法季节和为 0、乘法季节均值为 1），
最终状态的季节槽按「槽 0 对应未来第 1 步」规范化。

### SSE 与 AIC

高斯一步误差下：

```
AIC = n·(ln(2π) + ln(SSE/n) + 1) + 2(k+1)
```

`n` 为贡献 SSE 的观测数，`k` 为被估计的平滑参数个数
（无趋势：α,γ=2；有趋势：α,β,γ=3；阻尼再加 φ=4），`+1` 为误差方差。
自动选型取可行组合中 AIC 最小者。

### 预测与区间

点预测由最终状态直接递推（阻尼用
`b·φ(1-φ^h)/(1-φ)` 累积趋势）。区间两种做法，可在页面选择：

1. **解析近似（默认）**：线性误差状态空间（Gardner 等价误差形式
   `l_t=l_{t-1}+φb_{t-1}+αe_t`、`b_t=φb_{t-1}+αβe_t`）下 h 步预测误差
   方差为 `σ²·Σ_{i=1..h} ψ_i²`，其中

   ```
   ψ_1 = 1
   ψ_h = α + αβ·(φ+φ²+…+φ^{h-1}) + γ(1-α)·𝟙{(h-1) 是 m 的整数倍}   (h≥2)
   ```

   φ=1 时括号内即 h−1；无趋势时去掉 β 项。季节冲击
   `s_t = … + γ(1-α)e_t` 恰好在 m 步后被消费，因此 γ 项每过一个完整季节
   出现一次。该闭式系数已用残差自助模拟数值校准（偏差仅模拟噪声量级）。
   加法模型用绝对残差估计 σ；乘法模型用相对残差 `e_t/ŷ_t`，
   区间为 `ŷ_h(1 ± z·se_h)`。
2. **模拟**：对残差（乘法时为相对残差）做有放回自助抽样，从最终状态
   正向传播 2000 条路径，取经验分位数。

两种方法都**强制半宽随步长单调不减**（累积最大值）——这是预测误差方差
正确累积应有的性质，也可消除自助抽样噪声导致的局部回缩；乘法区间下限
截断在 0。

### 拒绝规则（返回明确原因）

- 乘法季节要求序列全为正：出现 0 或负值 → 拒绝；
- 少于 `2m` 个观测 → 拒绝（无法估计初始分量）；
- 递推中水平/乘法季节指数变为非正 → 该组合标记失败并记录原因；
- 自动选型不会静默丢弃不可行组合，评分卡里带原因列出。

## 层级预测（门店—区域—全网）

在单序列能力之上新增一层最多三层的树：**叶子 = 门店序列，中间 = 区域，
顶层 = 全网**。单序列的上传/缺周提示、拟合、区间、回测、任务等既有功能
完全不变；门店序列挂进树里，它在单序列页算出的任何数字都不改变。

### 挂接规则（拒绝时点名到子节点）

区域/全网 **不接受单独上传历史**，其历史永远由下级逐周加总。挂接时
（前后端同一套规则、后端落库事务里再校验一次）：

- 所有门店叶子的季节周期、周数、起始周、结束周、逐周日期网格必须完全
  一致；不一致的每个子节点都会得到一条「哪个区域的哪个门店、差在周期/
  起始周/结束周/周数/第 k 周」的拒绝原因；
- 同一门店在一棵树里只能出现一次；每个区域至少一个门店。

树、每次层级预测、每次层级回测都存进现有 PostgreSQL，同一棵树的多次结果
可互相比较。

### 调和方法（选了什么、放弃了什么）

每个节点先各拿一份 **基础预测**：

- 门店叶子：直接使用它被引用的那次单序列拟合，调的是与拟合页同一个
  `forecast()`，点预测/区间与单序列页逐位一致；
- 区域/全网：用下级叶子历史逐周加总后的序列，按请求的选型（自动 AIC 或
  指定加/乘组合）现拟合并预测。

调和采用 **对角 WLS（加权最小二乘）线性调和**
（Hyndman et al. 2011 框架）：

```
tilde Y = S (S' W⁻¹ S)⁻¹ S' W⁻¹ · Ŷ = P_μ · Ŷ
```

`S` 为求和矩阵（每个节点=哪些门店之和），`W` 为对角矩阵、取各节点样本内
一步残差方差（无噪声时用相对地板 `1e-8·max` 托底，只保矩阵非奇异，不拉动
本来一致的结果）。

- **放弃 bottom-up**：父节点虽恒等于门店之和，但完全丢弃区域/全网自身的
  拟合信息——那恰是经理最关心的两层。
- **放弃 top-down**：偏信全网、按历史比例摊给门店，门店层被主观拉动。
- **采用 WLS**：残差小（更可信）的层权重大，三层信息都参与；调和后任意
  父节点每个预测日期都等于直接下级点预测之和（自检阈值 1e-9，远严于需求
  的百万分之一），三层同时成立；**只有一个下级的区域与其唯一门店逐日期
  恒等**（求和约束的结构性质，非特判）。

**对局部重算的影响**：`P_μ` 对全树是稠密映射，任一节点的基础值/权重变
化，理论上所有节点的调和值都要重新映射。因此「局部重算」= **只重算换了
拟合的门店及其祖先路径的基础预测与权重，其余节点复用上一次落库的基础
值；调和仍对整棵树重跑一次**。该路径与「整棵重算」的调和结果逐日期一致
（测试固定到 1e-9）。WLS 不存在 bottom-up 那种「只动一条路径、不碰兄弟
节点」的廉价增量，这是本取舍的明确代价。

### 调和后的区间

基础区间沿用各节点单序列的同一套（解析/模拟）机制。调和区间 **不重做联合
自助**，而是把同一线性映射 `P_μ` 作用到基础下/上限，再以调和点预测为中
心、对每节点半宽按步长取累积最大值——因此 **宽度随步长单调不减**。它是
真实联合预测区间的线性近似，不再严格保持单序列区间的名义覆盖率；叶子的
基础区间本身与单序列页完全一致。单孩子区域的调和区间与其唯一门店相同。

### 可追溯与过期

每次层级预测落库时逐节点记录引用：门店记它用的 **单序列 Fit id**
（`fit_refs`：series_id → fit_id），聚合节点记加总拟合的参数/SSE/AIC 快
照。任一门店之后有了更新的拟合（如锁参重拟），引用旧拟合的结果在列表/
详情里被 **读时标记为已过期**，并列出是哪些序列、用的哪次、最新是哪次，
不再当成最新数字，可一键重算。

### 并发与失败

- 任务启动在单事务内按 fit id 钉死并整行读出各门店要用的拟合，之后只用
  内存快照计算；既有 fit 行只增不改，重拟插入的是新行，所以任务进行中他
  人重拟不会造成「前几个节点旧、后几个节点新」，记录的版本就是实际使用的
  版本（PostgreSQL 下读取额外加 `FOR UPDATE`；有并发版本记录测试）。
- 任一节点失败（门店无拟合、聚合序列触发乘法拒绝等）都在写库 **之前** 报
  错，错误信息点名节点与原因，绝不留下半份调和结果（有测试）。

### 层级回测

对一棵树按滚动原点回测：每个原点只用截至该原点的数据，**在循环内** 重算
各节点（叶子切片、聚合切片逐周相加）基础预测并整树调和，再与留出实际值
比较；原点隔离同样用「原点之后注入极端值、该原点结果不变」证明（测试按
节点同时核对调和前/后点预测）。结果按层（门店/区域/全网）列出调和前与调
和后的 **MAE、MASE**（另附季节朴素基准），并给出逐原点 × 节点明细，便
于看出调和帮了哪层、伤了哪层。

### 页面

「门店—区域—全网」页：新建区域与全网节点、勾选现有门店挂入（本地即时按
同一套规则校验并列出拒绝原因，提交后后端再校验）；选中树后按节点查看
历史（聚合为加总）、基础预测与调和后预测及两者之差，过期结果醒目标记并
可一键重算；层级回测按层对照 MAE/MASE。所有数字由后端算出。

## 回测定义

给定起点 `origin_start`、步长 `h`、原点步长 `stride`：

- 对每个原点 `k`，**只用 `y[:k]`** 重新初值化、重新优化参数、重新拟合，
  再预测未来 h 步；
- **季节朴素基准**：`ŷ_{k+j} = y_{k+j-m}`（照抄上一季节）；
- 指标：
  - MAE = 平均绝对误差；
  - MAPE = 平均绝对百分比误差（实际为 0 的点跳过）；
  - MASE 尺度 `Q = mean_{t=m..k-1}|y_t - y_{t-m}|`（每个原点按其训练段
    重算），MASE = mean|e|/Q；
- 汇总在全部原点/步长上池化计算，逐原点指标也一并给出。

测试用「原点之后注入极端值、预测不变」证明第 k 个原点不使用未来数据。

## API 摘要

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/series` / `/api/series/{id}` | 列表 / 详情 |
| POST | `/api/series` | JSON 两列创建 |
| POST | `/api/series/upload` | multipart CSV 上传（返回缺周列表） |
| POST | `/api/fits` | 提交拟合任务（body 见 `schemas.FitRequest`） |
| GET | `/api/fits/by-series/{id}` / `/api/fits/{id}` | 历史拟合 / 详情 |
| POST | `/api/backtests` | 提交回测任务 |
| GET | `/api/backtests/by-series/{id}` / `/api/backtests/{id}` | 历史回测 |
| GET | `/api/hierarchy/trees` / `/api/hierarchy/trees/{id}` | 层级树列表 / 详情（含聚合历史） |
| POST | `/api/hierarchy/trees/validate` | 挂接预检（不落库，返回逐条 issues） |
| POST | `/api/hierarchy/trees` | 建树（挂接不符返回结构化 400 + issues） |
| POST | `/api/hierarchy/forecasts` | 层级预测任务（`mode=full`/`auto` 局部重算） |
| GET | `/api/hierarchy/forecasts/by-tree/{id}` / `/api/hierarchy/forecasts/{id}` | 历史层级预测（含 `is_stale`/`stale_detail`） |
| POST | `/api/hierarchy/backtests` | 层级滚动原点回测任务 |
| GET | `/api/hierarchy/backtests/by-tree/{id}` / `/api/hierarchy/backtests/{id}` | 历史层级回测（按层 MAE/MASE） |
| GET | `/api/jobs/{id}` | 后台任务状态/进度/结果 id |

任务为异步：POST 返回 job id，前端轮询 `/api/jobs/{id}`，
`status ∈ pending|running|done|error`，`progress∈[0,1]`。
